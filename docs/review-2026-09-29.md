# Review, 29 September 2026

A review of the finished repository, covering the statistics and the R code,
the Python counting and generation layer, and the documentation against the
four registrations. What follows is what it found and what was done. The
analysis itself did not change: every derived file reproduces byte for byte
before and after.

## What holds

- The four analysis scripts reproduce all 42 derived files byte for byte from
  the committed counts, and the tests pass.
- Every registered hypothesis is reported with its verdict, every deviation is
  filed on OSF, each registration predates the data it covers and postdates the
  commit it pins, and `data/frames.csv` has not changed since before Study 1
  was registered.
- Holm's correction is applied over exactly the registered sets in all four
  studies. No confirmatory analysis is reported that was not registered, and
  the exploratory findings keep that label.
- The model is a Poisson-lognormal GLMM with `offset(log(words))`, and its
  calibration against quasi-Poisson and negative binomial reproduces: 0.16 and
  0.15 against the filed 15-16%, 0.77 and 0.79 against 77-79%, 0.93 against
  93%, 0.91 and 0.89 against the registration's 89-91%.
- The committed counts re-derive exactly from the generated text, and all 26
  file hashes verify.

## Fixed

**`R/check-corpus-sizes.R` could never pass.** It joined the metadata's blog
and general sums onto all fifteen rows of `data/corpus-sizes.csv`, so the five
`all` rows came back NA and the script always stopped. It has been broken since
D2 added those rows, which are the offsets the confirmatory analysis uses, so
the primary result's denominators had no working check. The script now checks
the ten section rows exactly and the five `all` rows against the section total
and the 0.055-0.088% excess D1 records, which is the strongest check the
metadata supports. `data/corpus-sizes-template.csv` was missing the same five
rows, so filling in the template and running `R/analyse.R` failed; it now has
them. The README says what the two rules are.

**The genre test's result was not in the provenance chain.** `R/analyse.R`
computed the `variety:section` likelihood-ratio test and used it to choose
which secondary set to print, but wrote it to no file, while
`docs/study1-results.qmd` asserted the outcome in prose and hard-coded the
choice. The registration makes that test the rule for which set is
confirmatory, so it was the one claim in the document a reader could not check
and the one place the write-up could drift from the analysis. The test now goes
to `data/genre-test.csv`, the write-up quotes the statistic, df and p from it
and selects its table on the same value, and a `stopifnot` block guards the
prose claims as the other two write-ups already do.

**Study 4's H4 named two of the three categories.** The Olmo 3 report describes
the Gen-QA mix as increasing web, QA and instruction data. Web text carries the
family at 22.6 per million against QA's 11.9 and instruction's 8.2, and
supplies 1,488 of the 2,277 hits in the midtraining sample, so it is at least
as good a candidate as the two the write-up named. The write-up, the README,
the verdict string in `R/analyse-study4.R` and the family table's caption now
name the mix rather than one category in it, and say which of the three has the
highest measured rate.

**The combined-sections coverage figures do not reproduce.** Four places in the
repository, and the D2 justification filed on OSF, give 88-90% for the normal
reference and 92% for the t reference, and three of them tell the reader
`R/calibrate-composite.R` reruns it. Running that script end to end gives 0.90,
0.89 and 0.93 against 0.93, 0.92 and 0.96. The filed figures came from running
the combined block alone, where the random number stream starts in a different
place. The choice of the t reference is unaffected: it covers at least as well
as the normal in every condition in both runs. The four places now carry the
reproduced figures, and `docs/deviations.md` records the correction under D2,
where the two other stale sentences are already recorded. The same entry
downgrades "halved" to the direction only: the reduction in false positives is
consistent across all three conditions but its size is not resolvable at 150
replicates.

**Two scripts overwrote committed tables from a partial run.**
`python/count_study4.py --collect` wrote `data/study4/counts.csv` from whatever
parts it found: on a clean clone, where the per-shard SFT and DPO counts are
gitignored, the documented command cut it from 211 rows to 31 and exited 0.
`python/count_generated.py --dolma` wrote `data/counts-dolma.csv` before
building the topic table, so an empty directory truncated the file and then
raised IndexError. Both now stop before writing, and each has a test.

## Recorded, not changed

- The README states Studies 2 to 4 more strongly than their write-ups do, which
  carry "What this does not establish" sections it does not summarise. Its
  "training text of every stage" covers the four stages measured; the
  long-context data was not counted and RLVR has no response side.
- No dependency manifest. The README names five R packages; the code also needs
  MASS, jsonlite, knitr, tibble and tools, plus Quarto and a LaTeX engine. The
  Python side needs `modal`, `pytest`, `numpy` and `zstandard`.
- `data/topics.csv` cannot be regenerated or verified from the repository: its
  source file is third-party and uncommitted, no hash of it is recorded, and
  `python/sample_topics.py` has no tests. `clean_title` keeps the longer side
  of a separator, which selects the site name when it is longer than the post
  title, and 8.1% of the committed topics still contain a separator against the
  "about 5%" in the generation protocol.
- `python/framecount.py` does not fold U+2010, U+2011 or U+02BC, so a
  hyphenated compound fragments and a curly-apostrophe contraction is missed.
  Immaterial in the generated corpus; U+2011 is common in PDF-extracted text.
- Study 1's registration lists a precision check on F10 and F13 as exploratory.
  It was not run and its absence is not recorded in the write-up.
- `data/training-contrasts.csv` carries a p-value of 7.8e-149 for the whole-mix
  contrast, whose variance ignores the frame-by-source spread the study
  measures elsewhere. The write-up says the interval reflects counting noise
  alone and never quotes the p.
- D1 concludes the Total column is not used; D2 then makes it the primary
  offset. The difference is immaterial and the wording is not.
- The three frozen protocol documents state pre-deviation facts with no pointer
  to the deviations that revise them.

## Not checkable from the repository

The GloWbE counts, which are hand-entered from a rate-limited interface with no
API; precision and recall in the training corpora, since no text is retained by
design; and the Modal-side code paths, which need a GPU and network.
